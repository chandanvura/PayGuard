THE 60 SECOND ANSWER

Tell the engineering story.

PayGuard handles provider timeouts after a simulated charge. The API persists an UNKNOWN payment keyed for idempotency. A worker later queries the provider and reconciles it to SUCCESS. I tested the request flow in Java integration tests and on a GitHub runner, then deployed locally with Compose and Minikube and instrumented it with metrics and logs.

PRACTICE QUESTIONS

Questions to answer at interview.

Why is a timeout not a failed payment?

The provider could process the charge before losing the response. UNKNOWN preserves uncertainty until a status check settles it.

What does the idempotency key protect?

A repeated request with the same key maps to the existing payment record and returns the same ID.

What if an application pod dies?

Kubernetes starts a replacement. Payment state remains in PostgreSQL, whose persistent volume survives the application pod restart.

What is the difference between Terraform and Ansible here?

Terraform describes isolated Kubernetes resources. Ansible reads the live cluster and verifies expected operational state.

Can GitHub Pages host the payment API?

No. Pages serves these static explanations; GitHub Actions runs a temporary API for repeatable proof. The local workstation can run the complete stack; GitHub Pages shows dated Grafana and Prometheus captures produced by temporary GitHub runners.

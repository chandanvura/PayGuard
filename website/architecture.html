01 / SYSTEM DESIGN

How PayGuard works.

Trace one payment from the HTTP request through durable state, simulated provider uncertainty, recovery, and monitoring.

REQUEST FLOW

Five states in one story.

01POSTClient supplies Idempotency-Key and payment body.
02PersistAPI creates the payment in PostgreSQL.
03TimeoutFake provider stores SUCCESS but throws an exception.
04UNKNOWNAPI records uncertainty and schedules reconciliation.
05SUCCESSWorker checks provider; retry uses the same ID.

Follow PaymentService.java ↗, FakePaymentProvider.java ↗, and PaymentReconciliationWorker.java ↗.

PERSISTENCE

State survives the process.

PostgreSQL holds payments and the idempotency key. Flyway applies V1–V3 migrations; JPA validates the schema instead of changing it. Reconciliation metadata records attempts and the next check. Kubernetes uses a PVC for PostgreSQL. Read the table migration ↗
